Plan written 2026-09-21 against `browser-client` at `4e5e7db` (master). Executed by Opus agents per work package, in waves, in separate git worktrees off `browser-client`. The orchestrator merges each wave and runs the Deploy runbook. Agents do not edit this file.

## 0. How to read this

- Section 6 is the packages. Each is self-contained: read `docs/BROWSER_PLAN.md` sections 4-5 plus its own "Read first" list, touch only the files it owns, and pass its acceptance commands before handing back.

## 1. Goal

Turn HyruleLink's web page into the player client: the browser links to the game through SNI/QUsb2Snes on `ws://localhost:23074` (fallback `:8080`), detects pickups, applies grants and revokes, draws HUD lines, and talks to the same FastAPI server the desktop app uses, over the same `/ws` contract. Give it EtherNet's shape: room link as the key, graphite-and-gold look, operator page behind a key file, docs set, deploy script, fake game, node units in the test suite, and serve it at `https://www.billogna.lol/hyrulelink/` as well as `https://hyrulelink.billogna.lol`.

## 2. Non-goals

- No aiohttp rewrite. The FastAPI server and `server/ledger.py` stay.
- No in-browser seed generation. Players bring a seed from alttpr.com.
- No same-seed sync, no host-sets-seed, no race clock.
- No removal of the desktop app or its routes; it keeps seed generation, emulator launch, direct NWA/RetroArch transports, and the BillognaBot HUD hand-off.
- No Discord login on the web page. The server keeps `/auth/*` and the Discord-session admin for the desktop app.
- No new dependencies for the server (`requirements.txt` unchanged). Dev-only deps go in `requirements-dev.txt`.

## 3. Decisions (fixed)

1. Browser page = player client, via usb2snes like EtherNet. Port agent.py / effects.py / item_effects.py / memory constants to JS. Copy snes.js, hud.js, fake_snes.py from EtherNet and adapt; HyruleLink reads inventory and writes items, which EtherNet's "only the module byte" rule forbids, and its docs say so.
2. Python server stays FastAPI.
3. Desktop app and existing protocol keep working. Browser agent and Python agent are interchangeable on `/ws` (`role: "agent"`). No route the desktop app calls changes shape (list in 4.2).
4. Room link is the key. Seat (player_id + player_token) lives in localStorage; reopening resumes the same player. Web global-admin = `operator.html` behind a key file. Discord auth endpoints stay server-side.
5. Look: graphite and gold, EtherNet/QuakeCast tokens, type, radius scale, nothing animates at rest. Item sprites stay. The aurora palette and the `/shared/` billogna.lol chrome go.
6. Seeds: link out to alttpr.com.
7. Served under `www.billogna.lol/hyrulelink/` (prefix stripped by nginx, relative URLs only, test-enforced) and on `hyrulelink.billogna.lol`; one service behind both.
8. Docs set, deploy script, ServiceHub entry, JS tests in the unittest suite and CI, fake game. Plain short wording, no exclamation marks, no tutorial voice.
9. QuakeCast hook only if cheap and clean; last package, droppable.

## 4. Current-state findings that matter

### 4.1 Server and protocol (server/app.py, server/ledger.py, shared/protocol.py)

- One WebSocket `/ws`. First message is `hello`. `role` is `agent`, `ui` or `spectator`.
  - `agent` / `ui`: `{type:"hello", role, room:<CODE>, player_id:<int>, token:<player_token>}`; validated by `db.player_by_token(code, player_id, token)`; a bad token gets `{type:"reject", reason:"bad room/player token"}` and a close.
  - `spectator`: `{type:"hello", role:"spectator", watch:<pub_id>}` (a raw code is also accepted); no player, no claims.
  - Admin comes from the Discord session: browser cookie `hl_session` or a `session` field in hello (desktop app). The browser page will not use either.
- Agent socket (`_serve_agent`): on hello the server registers the agent (`hub.agents[code][player_id] = ws`; ONE per player, a newer registration replaces the older; `unregister_agent` only clears if it is the same ws), pushes an exhaustive `ownership_commands` set (one `grant {item, level}` or `revoke {item}` for EVERY catalog item, 31 messages) and broadcasts state. It then accepts `pickup {item, level}`, `resync {}` (re-push ownership), `status {emu: bool}`, `applied {item, action, ok, error?}`, `bye`. It sends `grant`, `revoke`, `notify {text}`, `reject {reason}`.
- UI socket (`_serve_ui`): first message is the full state doc with `you`, `admin`, `spectator`, and (only in this first message) `items: [{key, name, image}]` (the catalog for watchers). Then `claim {item}` and the `admin_*` messages (host only, or a Discord admin). Every change rebroadcasts a `state` doc without `items`, plus `event {text, ts}` lines.
- State doc (`RoomHub.serialize`): `{type:"state", room:<pub_id>, name, cooldown_s, host, mode, rules, rule_defaults, rule_presets, claiming, rules_summary, shuffle_s, shuffle_remaining, players:[{id, name, avatar, agent, emu}], ledger:{key:{name, owner, owner_name, level, tier, image, discovered:[ids], discovered_levels:{id:lvl}, cooldown_remaining, hold_remaining?, locked?, tenure_remaining?, borrow_remaining?}}}` + `you`, `admin`, `spectator`. Only discovered-or-owned items appear in `ledger`. `room` is the public handle; the join code is never in it.
- REST used by the web today: `GET /api/rooms` (public list: pub_id, name, players, player_list, last_active, login_enabled), `POST /api/rooms {display_name, name?, cooldown_s?}` -> `{code, pub_id, name, cooldown_s, host, player_id, player_token, players, items}`, `POST /api/rooms/{code}/join {display_name}`, `POST /api/rooms/{code}/resume {player_id, player_token}` (same payload), `POST /api/rooms/{handle}/delete` (Discord admin), `/api/me`, `/api/my-rooms`, `/api/rooms/{code}/rejoin`, `/auth/*`, `/health`, `GET /` (index.html), `/static/*` (web/).
- Rate limits: create 10/min, join+resume 20/min, device-login 10/min per client IP (`rate_limit.client_key` takes the LAST hop of X-Forwarded-For when the peer is loopback).
- Static: `web/` is mounted at `/static`; `index.html` hardcodes `/static/...` and `/shared/...` (an nginx alias to billogna.lol's asset dir that only exists in the subdomain's server block). Both break under a path prefix.
- `auth_callback` redirects to `/` and `device_start` builds `login_url` from `request.base_url`: both assume the subdomain. The desktop app uses the subdomain, so leave them.
- Room codes are 10 chars of `ABCDEFGHJKLMNPQRSTUVWXYZ23456789`; `pub_id` is `token_urlsafe(9)`; player tokens `token_urlsafe(18)`. Rooms idle 14 days are pruned twice a day.
- `db.py` and `ledger.py` need no changes for this build. Do not touch them unless a package says so.

### 4.4 Agent subtleties the JS port must preserve (agent/agent.py, effects.py, sni/item_effects.py; tests/test_effects.py is the spec)

- Tracked range: every item address from `shared/items.py`; contiguous read of `[min, max]` = `0xF342..0xF38E` (77 bytes) once per poll. `0xF379` (abilities) sits inside it and is read from the same snapshot.
- Pickup detection per address: first sight seeds the baseline silently; if the byte equals `expected[addr]` it is our own write echoing back (accept, clear expected, no report); if unchanged, skip; else for every item on that address report `pickup` when `discovered_level(item, new) > discovered_level(item, old)`, then baseline = new. Several items share a byte (`0xF38C` bitfields).
- Game-mode gating: poll only in PLAYABLE `{06,07,08,09,0A,0B,0E}`. Seeing an OUT_OF_GAME module `{00,01,02,03,04,05,14,17,1B}` sets a flag; the next playable poll does `resync(wipe=True)`: clear baseline+expected, `hud.reset()`, send `resync`. Death (`0x12`), door spotlights, mirror, boss victory are NOT out-of-game and cause no resync.
- Transport blip (bridge dropped and came back, same save): `resync(wipe=False)`: keep the baseline so a pickup made during the blip is still reported; send `resync` and `status`.
- Apply (grant/revoke): read the module first; outside PLAYABLE, put `{level, enable}` in `pending[key]` (newest command per item wins) and return; the next playable poll flushes pending BEFORE taking the snapshot. Otherwise try up to 3 times (writes are idempotent), record `expected[item.addr] = raw` on success, send `applied {item, action, ok}` (`error` truncated to 200 chars on failure).
- Effects: progressive = write the exact level (never +1); simple = write `give` (Mirror is 2; 1 is a broken icon); boots = `0xF355` + set bit `0x04` of `0xF379`, revoke clears both; bow = `0xF38E` bits `0x80` has / `0x40` silver are authoritative, `0xF340` equip = 1 wood / 4 silver / 0 none, silver also writes 30 arrows into `0xF377` if it reads 0; shared-slot items own bits in `0xF38C` (blue 0x80, red 0x40, mushroom 0x28 set / 0x20 own, powder 0x10, shovel 0x04, flute 0x01 active / 0x03 any) and keep the enum slot bytes (`0xF341` boomerang 1/2, `0xF344` mushroom 1 / powder 2, `0xF34C` shovel 1 / flute 2 inactive / 3 active) in sync, falling back to the other half on revoke, never OR-ing the enum. Every enable/disable verifies by reading back and throws on mismatch.
- Reads inside read-modify-write retry 6 times and NEVER fall back to 0 (a 0 would clobber the other bits of `0xF379`, `0xF38C`, `0xF38E`).
- Boots enforcement every poll: if boots owned and bit 0x04 clear, set it; if not owned and set, clear it; write only when wrong.
- `notify {text}` -> HUD strip line (only drawn while playable; queue of 6, immediate duplicates dropped) + page toast/log. RetroArch OSD and the BillognaBot `/api/hud/say` hand-off are desktop-only and are not ported.
- `status {emu}` on server-socket open and whenever the game link changes.
- Improvement over Python (keep it): pickups that cannot be sent (agent socket down) go to an outbox and are flushed right after the next hello, so a find made during a server outage is not revoked by the reconnect ownership push.

### 5.4 WebSocket contract

Unchanged (shared/protocol.py). The browser player page opens TWO sockets: `ui` (board, claims, host controls) and, once a game is attached, `agent`. Spectators open one `spectator` socket with `watch: pub_id`. `status {emu}` is sent on agent-socket open and on every attach/detach. ## 8. Risks and containment

| Risk | Containment |
|---|---|
| A page cannot reach `ws://localhost` from https | Proven by EtherNet in Chrome/Edge/Firefox (Private Network Access prompt: allow). Safari unsupported; USING.md says so. The desktop app remains. |
| Writes through QUsb2Snes unproven; FXPak writes go through the cartridge hook | USING.md recommends SNI (writes proven by EtherNet's hud_check); the fake proves the logic; the desktop app is the fallback. |
| Two agents for one player (second tab, phone, desktop Connect) | Agent socket opens only on first attach; "Link a game on this browser" switch; newest registration wins, documented. |
| Grant and poll interleave in async JS | One promise chain in agent.js; a unit test asserts no interleaving. |
| 31 ownership commands on every agent hello over a slow bridge | Sequential through the chain, verified per write; tests run it against the fake; `applied` failures surface once per item in the activity log. |
| Background tab throttling | Worker ticker from snes.js; do not move game work to plain timers. |
| Prefix serving breaks a URL | Relative URLs, test-enforced; `location = /hyrulelink` redirect; the `/static` alias stays for stragglers. |
| Discord device flow under the prefix | Only used by the desktop app on the subdomain; documented. |
| nginx map name differs | `nginx_install.py` refuses to insert if `race_connection_upgrade` is not in the file. |
| CRLF in deploy.sh breaks the ssh heredoc | `.gitattributes` forces LF; acceptance checks with `file`. |
| CI node too old for the harness | `actions/setup-node@v4` node 22; units fake WebSocket and need no version. |
| Droplet memory | The server is ~60 MB; `MemoryMax=300M`; no new server deps. |
| Old browser seats (`hl_rooms`) lost | Imported into `hyrulelink.rooms` on first load. |
| Rate limits hit by page reloads (resume 20/min) | Resume is one call per load; fine. |
| Operator delete by mistake | Two-click arm plus a third confirmation when someone is in the room. |
